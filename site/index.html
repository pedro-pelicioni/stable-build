The builder journey for apps built on Arc

Skills, a payouts starter, an opt-in edit-time guard and a go-live checklist for Claude Code and Codex. From “what should I build?” to a mainnet readiness report.

Install with one command

curl -fsSL https://raw.githubusercontent.com/pedro-pelicioni/stable-build/main/install.sh | bash

It asks before adding Circle’s skills, the Arc Studio plugin and the guard; the docs MCP servers are added by default (--no-mcp skips them). Run it in a normal terminal, not inside an agent session. To read the script first, preview the plan with --dry-run.

What one command installs

Plugins are added by the hosts’ own claude plugin and codex plugin commands, and the Arc Studio plugin by its own CLI. Circle’s skills and the Arc Studio plugin need your yes; the MCP plugin is added by default. Each optional piece has a flag to skip it.

  • stable-build skills and guard

    stable-build, MIT

    16 skills for the journey, from guide and find-idea to go-live, plus the guard hook, which stays off until you opt in.

  • Circle’s skills

    Belongs to Circle, Apache-2.0

    Circle’s circle-skills plugin, fetched from circlefin/skills and not bundled. stable-build skills hand product questions to it. Installing it accepts Circle’s developer terms, so the installer asks first.

    circlefin/skills Skip: --no-circle

  • Arc Studio plugin

    Belongs to Circle

    Circle’s hosted agent that writes, audits and deploys contracts, to Arc testnet only. If the arc-studio CLI is installed and you agree, the installer registers its Claude Code plugin. You log in to Arc Studio yourself.

    Arc Studio CLI docs Skip: --no-studio

  • Arc docs MCP and Circle codegen MCP

    stable-build config (MIT) pointing at hosted servers run by Arc’s docs site and Circle

    The optional stable-build-mcp plugin adds the Arc docs server (https://docs.arc.io/mcp) and, in Claude Code, Circle’s codegen docs server (https://api.circle.com/v1/codegen/mcp). In Codex it adds only the Arc docs server, because Circle’s Codex plugin brings its own. It is added by default; in Claude Code the installer then checks both servers once with claude mcp get. Queries you send them go to docs.arc.io or to Circle.

    Arc MCP docs Circle MCP docs Skip: --no-mcp

A guard that reads each edit for Arc gotchas

An advisory check that runs after each Write/Edit (Claude Code) or apply_patch (Codex) inside an Arc project and looks only at the lines just added.

Why the filter below is wrong on Arc

One ERC-20 USDC transfer logs twice: from 0x3600… at 6 decimals and from the system emitter at 18. A plain native send logs only from the system emitter, so a 0x3600… filter misses it.

USDC system events on docs.arc.io

  1. 1 The agent writes a USDC history query

  2. 2 The guard answers right after the edit

    stable-build guard: 1 Arc gotcha in src/history.ts (transfer-filter-no-emitter) — advisory, edit kept

    That one line is for you. The agent gets the details as added context.

    What the agent receives (in English) 
    stable-build guard: 1 Arc gotcha in the lines just written (0 error, 1 warn).
- [warn] transfer-filter-no-emitter at src/history.ts:9: Filter on the ERC-20 USDC address (0x3600…) only: plain native USDC sends are missed. The system emitter logs every USDC movement, ERC-20 transfers included. Fix: Replace 0x3600… with the system emitter 0xffffFFFfFFffffffffffffffFfFFFfffFFFfFFfE (18 decimals). Do not query both: each ERC-20 transfer would come back twice. Docs: https://docs.arc.io/arc/references/usdc-system-events says "The native system emitter logs a `Transfer` for every explicit USDC transfer—native sends, ERC-20 transfers, mints, and burns—at 18-decimal precision." (checked 2026-10-05)
advisory: the edit was applied; silence with `stable-build-ignore <id>`

  3. 3 The agent applies the fix

    Only the changed lines are shown, numbered as in step 1. The guard checks the new lines again and prints nothing.

Off until you opt in.
The hook launcher exits without starting Node unless ~/.stable-build/config.json contains "guard": true. Codex also requires you to trust the hooks in /hooks.
Advisory.
The edit is already applied. The guard never blocks, undoes or rewrites it, and it always exits 0. At most 5 findings per edit.
Local.
No network calls, no file writes, no telemetry. If anything fails, it exits 0 quietly.
Arc projects only.
A project counts when it has .stable-build/project.json, or a marker such as chain id 5042 or 5042002, arc/arcTestnet from viem/chains, an rpc.*.arc.io URL or the USDC address 0x3600…0000.

10 rules, each tied to a docs page

Each rule’s docs quote and verified_at date are in data/gotchas.json. Scan a repo without the hook: node <plugin>/scripts/guard.mjs --scan .

  • usdc-native-value-6dp error

    Native value or msg.value built with 6 decimals; native USDC uses 18.

  • usdc-erc20-amount-18dp error

    USDC transfer / approve / transferFrom with 18-decimal amounts; the ERC-20 interface uses 6.

  • usdc-balance-summed error

    getBalance added to balanceOf: one balance, two views.

  • fee-below-floor error

    maxFeePerGas or gasPrice under 20 gwei; such transactions never get a receipt.

  • getlogs-unpaged error

    Log queries from a fixed block to latest without paging, or ranges over 10,000 blocks.

  • transfer-filter-no-emitter error warn

    Transfer filters that count ERC-20 transfers twice, or watch only 0x3600… and miss native sends.

  • cctp-stellar-no-forwarder error

    CCTP burn to Stellar (domain 27) whose mintRecipient or destinationCaller is not CctpForwarder.

  • upstream-foundry warn (error in CI)

    Upstream Foundry, or arc-forge test / arc-anvil without Arc mode, which run Ethereum rules.

  • extension-from-smart-account error

    Memo or Multicall3From used from a smart account, Safe, bundler or another contract; they accept only a direct EOA caller.

  • multicall3from-value error

    aggregate3Value, or value on aggregate3 through Multicall3From, which forwards no value.

From idea to go-live

Start with /stable-build:guide: a read-only check of your setup that asks your stage and names the next skill. In Claude Code, run a skill as /stable-build:<name>; in Codex, ask for it by name.

  1. 1

    find-idea

    A short interview, then 5 ranked ideas grounded in Arc’s Request for Builders, live building blocks, sample apps and current programs, each with sources, deadlines and a first-2-hours plan.

  2. 2

    new-app payouts starter

    Scaffolds into an empty folder you name. Testnet by default.

    1. CSV of recipients
    2. One Memo.memo(USDC.transfer) per row
    3. Batched through Multicall3From from an EOA
    4. Reconciled from receipts into an 18-decimal ledger

    Rerunning resumes the batch and skips paid rows.

  3. 3

    Role skills

    analyst
    brainstorming and quick research
    pm
    PRD with an Onchain section
    ux-designer
    UX specs with Arc states
    architect
    starts from Arc’s protocol invariants
    dev
    one story at a time, test first
    tech-writer
    a docs.arc.io source for every Arc fact

    A story is done only with passing tests and a recorded testnet transaction hash. The role skills are adapted from BMad Method v6.12.1 (tech-writer from v6.10.0), MIT.

  4. 4

    go-live

    Testnet-to-mainnet checklist: 14 gates, each marked with evidence, written to docs/go-live-report.md. Never deploys and never touches keys.

  2. new-app
  3. product-brief / pm / ux-designer / architect / stories

Install three ways

Requirements: Node.js 20 or newer, plus Claude Code 2.1.280 or newer and/or a Codex CLI that has codex plugin. The installer needs bash 3.2 or newer (the macOS default works).

Installer, for Claude Code and Codex

Asks before adding Circle’s skills, the Arc Studio plugin and the guard. Rerunning it is safe: it changes nothing that is already in place.

Installer one-liner

curl -fsSL https://raw.githubusercontent.com/pedro-pelicioni/stable-build/main/install.sh | bash

To read it first, download it, then preview the plan:

curl -fsSLO https://raw.githubusercontent.com/pedro-pelicioni/stable-build/main/install.shbash install.sh --dry-run

When you are happy with the plan, run it:

bash install.sh
All installer options
Installer options and their effect
OptionEffect
--dry-runPrint every planned action and change nothing
--yesAccept every prompt, including turning the guard on (a guard you declined earlier stays off)
--no-hooksLeave the guard off and do not ask, now or on later runs
--no-mcpSkip the stable-build-mcp plugin
--no-circleSkip Circle’s skills plugin
--no-studioSkip the Arc Studio plugin
--updateUpdate stable-build, plus Circle’s and Arc Studio’s plugins if this installer added them. Never turns the guard on
--uninstallRemove only what this installer added
--ref=TAGInstall a tag or branch (default main, which moves only at releases)
--prefix=DIRSandbox: every CLI call runs with HOME=DIR, so nothing outside DIR is written
--lang=LANGLanguage of the installer and of the kit’s replies, en or pt-BR; saved for later runs

With no terminal attached (or inside a Claude Code or Codex session) and no --yes, the installer adds only stable-build itself: Circle’s plugin and the Arc Studio registration are skipped, the guard stays off, and it tells you how to add them later.

Claude Code, with /plugin

stable-build-mcp is optional. To turn the guard on, run /stable-build:gotchas enable; the skill explains the guard and asks before it writes anything. Start with /stable-build:guide.

Run these in Claude Code, one line at a time:

  1. /plugin marketplace add circlefin/skills
  2. /plugin install circle-skills@circle
  3. /plugin marketplace add pedro-pelicioni/stable-build
  4. /plugin install stable-build@stable-build
  5. /plugin install stable-build-mcp@stable-build
  6. /reload-plugins

Codex, with codex plugin UNVERIFIED: not run yet

stable-build-mcp is optional; in Codex it adds only the Arc docs server, because Circle’s Codex plugin brings its own. If you turn the guard on, also open /hooks in Codex and trust the stable-build hooks: Codex skips plugin hooks until you do.

What it touches

  • The installer itself writes only under ~/.stable-build: manifest.json, with what it added, and config.json, with your language and, once you agree, the guard switch ("guard": true).
  • Everything in Claude Code’s and Codex’s folders is written by their own claude plugin and codex plugin commands. The installer never edits settings.json, .claude.json, config.toml or hooks.json by hand.
  • Network use at install: the plugin CLIs clone pedro-pelicioni/stable-build and circlefin/skills from GitHub, and in Claude Code the installer checks the two MCP servers once with claude mcp get.
  • Never touched: shell profiles, PATH, global npm packages, permission allow-rules, other plugins or skills you already have, any login or token, and your projects.
  • No telemetry, analytics or install counters, in the installer, the hooks or the skills.

The complete list, file by file, is in the README

Uninstall

curl -fsSL https://raw.githubusercontent.com/pedro-pelicioni/stable-build/main/install.sh | bash -s -- --uninstall

It removes, in reverse order, only what its manifest says it added, and asks before removing Circle’s plugin. It never runs arc-studio logout.

English and Português

The installer, the guard’s one-line warning, the session-start notice and what the skills write for you (chat replies, docs/go-live-report.md, PRDs, stories, idea lists) come in English or Brazilian Portuguese (pt-BR). The installer’s first question is “Language / Idioma”. To answer it up front:

If you downloaded install.sh:

bash install.sh --lang=pt-BR

Or with the one-liner:

curl -fsSL https://raw.githubusercontent.com/pedro-pelicioni/stable-build/main/install.sh | STABLE_BUILD_LANG=pt-BR bash

The choice is saved as "language" in ~/.stable-build/config.json; saving it does not turn the guard on. Code, file names, rule ids, CLI flags and commit messages stay in English.
