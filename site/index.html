01 The team

Meet your team

Six specialists who know Arc. Call one by name, or just say what you need.

  • Tim

    Architect

    Team lead

    Leads the plan. Starts from Arc invariants like decimals, the fee floor and finality, then checks the plan is ready to build.

    “Tim, design the architecture” /stable-build:architect

  • Bobbilee

    Product manager

    Writes the PRD with an onchain section: network plan, fees in USDC, EOA or smart account.

    “Bobbilee, write the PRD” /stable-build:pm

  • Sam

    Analyst

    Brainstorms and researches, then ranks ideas against the Request for Builders and open programs.

    “Sam, what should I build on Arc?” /stable-build:analyst

  • Joshua

    UX designer

    Specs screens with Arc states built in: one USDC balance, pending then final, a testnet banner.

    “Joshua, design the payout screens” /stable-build:ux-designer

  • Pedro

    Developer

    Builds each story test-first on Arc Foundry. Done means green tests and a testnet tx hash.

    “Pedro, implement the next story” /stable-build:dev

  • Mike

    Tech writer

    Docs, explainers and diagrams, with every Arc fact linked to docs.arc.io.

    “Mike, document this flow” /stable-build:tech-writer

  • + Layered review: five independent passes, one of them an Arc gotcha hunter.
  • + Arc Studio: hand off contract writing, audits and testnet deploys.

The names are a tribute to people from the Arc community, with the kit’s author as the developer. They did not build or endorse this kit, and the agents never speak for them or for Circle.

02 The journey

From idea to mainnet

Each step leaves a file in your repo that the next one reads, so nothing gets lost between chats.

  1. 1

    Idea

    5 ranked ideas from the Request for Builders, each with a first-2-hours plan.

  2. 2

    Plan

    Brief, PRD, UX, architecture and stories in docs/plan.

  3. 3

    Build

    Start from the payouts starter, then ship story by story, test-first.

  4. 4

    Review

    Five review layers, each finding verified before it reaches you.

  5. 5

    Go live

    14 gates before mainnet. It never deploys and never touches keys.

03 Arc-native

Built for how Arc actually works

Arc is EVM, with differences that break code written the Ethereum way. The kit knows them.

A guard that reads every edit

An opt-in check reads the lines the agent just wrote for 10 Arc mistakes, each tied to a docs page. Advisory: your edit is kept.

stable-build guard: 1 Arc gotcha in src/history.ts (transfer-filter-no-emitter) — advisory, edit kept

Native USDC sends log only from the system emitter, so this filter misses them. Why, on docs.arc.io

Payouts starter

CSV in, one Multicall3From batch with a Memo per row, reconciled ledger out. Testnet by default.
