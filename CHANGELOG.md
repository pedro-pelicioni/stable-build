# Changelog

This file lists the notable changes to stable-build. It follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and version numbers follow [Semantic Versioning](https://semver.org/).

Every release does three things:

- Bumps `version` in all four plugin manifests and in the root `package.json`. Claude Code keeps users on a version until it changes. `node tools/check-names.mjs --release-tag vX.Y.Z` checks that they all agree.
- Records the upstream versions it was tested against, including the circlefin/skills commit, since that repo has no tags.
- Calls out changes to the guard's rules and any Arc fact that was re-verified.

## [Unreleased]

### Added

- English and Brazilian Portuguese (`pt-BR`) across the kit.
  - Installer: `--lang=<v>` or `--lang <v>`, and `STABLE_BUILD_LANG`. Accepted values, in any case: `en`, `english`, `pt`, `pt-br`, `pt_BR`, `portugues`, `português`. In a terminal, the first prompt is "Language / Idioma: [1] English [2] Português (Brasil)", and Enter keeps English. English is the default everywhere: the locale (`LANG`, `LC_ALL`, `LC_MESSAGES`) is never read, and with no terminal, with `--yes` or in an agent session the installer uses English without a prompt. Precedence: `--lang` > `STABLE_BUILD_LANG` > the saved choice > the prompt > English. An unknown value exits 1 with a bilingual error. Every message, `--help` and argument errors come from two message tables (`_msg_en`, `_msg_pt`).
  - The choice is saved as `"language"` in `$STABLE_BUILD_HOME/config.json` (atomic write, other keys kept; it never turns the guard on, which still needs `"guard": true`). The manifest records `language` and whether `config.json` was `createdByUs` (or only got `languageAddedByUs`), so `--uninstall` deletes `config.json` only when the installer created it and otherwise removes only the keys it wrote. Reruns, `--update`, `--uninstall` and `--help` reuse the saved choice; `--help` reads it from the `--prefix` sandbox whether `--prefix` comes before or after it. Spaces around a saved value (and around `--lang` and `STABLE_BUILD_LANG` values) are ignored in the installer and the hooks alike.
  - Hooks: the guard's one-line `systemMessage` and the SessionStart notice follow the saved language (`scripts/guard/prefs.mjs`), and `guard.mjs --status` reports it. With `pt-BR` saved, the SessionStart output adds one English line telling the agent to reply in Brazilian Portuguese even when the user writes in English, so plain turns outside a skill follow the saved language too (the hooks run only after guard consent and print only in an Arc project). The agent-facing context, rule ids and docs quotes stay in English.
  - Skills: every `SKILL.md` has a `## Language` section. Skills read the saved language once per session and write replies and generated documents in it; with none saved they answer in the user's language.
  - `find-idea`: a pt-BR output template with Portuguese field labels and values. `lint-ideas.mjs` accepts it, checks the wording rules in Portuguese as well (for example "rendimento", "rentabilidade", "lucro", "retorno garantido", "renda passiva", "juros" someone earns, "garantido", "sem risco", "app oficial", "parceria com a Circle"), and recognizes Portuguese key labels ("chave privada") and hash words ("tópico", "transação").
  - Docs: `README.pt-BR.md` and the payouts template's `README.pt-BR.md`. `tools/check-docs-sync.mjs` keeps each translation in step with its English original (headings, code blocks, cross-links, anchors); it runs in `npm run check`, CI and the release workflow.
  - Tests: `test/install/i18n.test.mjs` (both message tables complete, matching placeholders and argument counts, no untranslated or literal prose), language scenarios L1 to L6 in `test/install/roundtrip.sh`, a pseudo-terminal test of the prompt (`test/install/tty-drive.py`, needs python3), and `test/guard/language.test.mjs` and `test/skills/language.test.mjs`.
- Landing page in `site/`: a static page (no framework, no build step, dark only) with an EN/PT toggle. A hero with the one-line install and an animated session from idea to go-live, the six role skills as a team (each with a sample ask and its slash command), the journey in five steps, and a bento of what is specific to Arc: the guard with its real output on a sample file, the payouts starter, Circle's skills and Arc Studio, EN/PT and safety. Install options, the rule list and uninstall details live in the README, which the page links to. Motion respects `prefers-reduced-motion`. English is the default: Portuguese shows only after the visitor presses PT (remembered) or with `?lang=pt`, never from the browser language; the Portuguese copy then loads and is applied before the first paint. Wording follows the Arc partner toolkit: "Arc Network" on first mention, no possessive "Arc's", and the Arc trademark line in the footer. Open Graph image and `vercel.json` included.
  - `test/site/site.test.mjs`: the page's install command is the README's, the team cards are exactly the catalog's role skills, the gate, rule and idea counts match the skills and `data/gotchas.json`, the guard card is the guard's real output (notice in both languages, flagged line), every translatable key has Portuguese copy, every id the page points at exists, and the brand wording holds. `tools/check-links.mjs` now also checks `site/` (bare origins in preconnect hints and CSP sources are not fetched).
- Persona names for the six role skills, so a builder can say "talk to Tim": Tim (`architect`, leads the plan), Bobbilee (`pm`), Sam (`analyst`), Joshua (`ux-designer`), Pedro (`dev`) and Mike (`tech-writer`). Each description triggers on its name, replies start with `[Name · role]`, and each skill carries a rule never to claim to be that person or speak for them or for Circle. The names are a tribute to people from the Arc community (the kit's author is the developer); the guide, both READMEs, the landing page and the installer's closing lines list the team. `test/site/site.test.mjs` checks that the names agree everywhere.

### Changed

- Installer v2: one question, then everything a builder needs, in about 20 lines.
  - Prompts: the language (only when not given or saved), then one confirmation that lists only what is missing ("Continue? [Y/n]"; "Continuar? [S/n]" in pt-BR). A yes covers the whole list: Circle's plugin (the bullet links the Circle Developer Terms), the guard, the npm install, the Arc Foundry download and the rc-file lines. A "no" changes nothing and exits 0. On `--update` the update itself needs no yes: the question ("Add these too?") lists only what needs one and is not set up yet, and a "no" skips just those items while the update goes on. Nothing missing, no question. Only Enter takes the default: spaces around an answer are ignored, any other answer that is not a yes or a no is asked again ("Type y (yes) or n (no)"), and three of those, or Ctrl+D, count as no, so a typo such as "nope" or "n " never accepts Circle's terms. When the Arc Studio sign-in is all that is missing (a rerun or `--update` after an install with `--yes`), the question is "Sign in to Arc Studio now?" and a no skips only the sign-in, so `--update` still applies its updates. The separate Circle, Arc Studio and guard prompts are gone, and so are the six-line Circle disclaimer and the guard explanation. The language just chosen is no longer echoed (the confirmation is already in it), which keeps a fresh install with both Claude Code and Codex within 25 lines.
  - Output: a one-line header (`stable-build 0.1.0 · Claude Code … · Node …`; an old Codex is a "Codex skipped (needs a newer Codex)" suffix), one `✓`/`–`/`✗` line per component, and a short closing with the team and the paid-services note for Circle's skills when they are present. Raw CLI output goes to `$STABLE_BUILD_HOME/install.log` (overwritten each run); a fatal failure prints the last 15 lines of that command's output and the log path. The plan table shows only with `--dry-run`; `--verbose` prints every command and its raw output, the full header and section titles.
  - Arc Studio: when `arc-studio` is missing (on `PATH` and in `$(npm prefix -g)/bin`) and npm is there, `npm install -g @circle-fin/arc-studio-cli@latest`, then `arc-studio skills install --tool claude-code` (Claude Code only), then the sign-in: `arc-studio login` on the terminal (Ctrl+C cancels only the sign-in), unless `arc-studio whoami` says you are signed in, `--no-login` was given, or nobody can answer (`--yes`, no terminal, an agent session), which print "sign in later". Under `--prefix`, npm uses `npm_config_prefix=$PREFIX/.npm-global` and the sign-in uses `--paste`, so the token stays in the sandbox. npm and sign-in failures are one `✗` line with the fix, not fatal. The manifest records the npm prefix the CLI went into. `--update` reinstalls the CLI from npm when this installer added it in the prefix now in use (after a node switch, a copy in the new prefix is someone else's and is left alone), then runs `claude plugin marketplace update arc-studio-cli` and `claude plugin update arc-studio@arc-studio-cli`, because Claude Code runs its own copy of the plugin (a failure there is one `✗` line). `--uninstall` removes the plugin, then runs `npm uninstall -g` in the recorded prefix (or says the CLI is already gone instead of claiming it removed it), and never runs `arc-studio logout`.
  - Arc Foundry: when `arc-forge` is missing, the release for the platform (`aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`; tag from the GitHub API or `STABLE_BUILD_FOUNDRY_TAG`) is downloaded with its `.sha256`, verified, and installed as `~/.local/bin/arc-forge`, `arc-cast` and `arc-anvil` (0755), after `arc-forge --version` has run from a staging directory next to them: a release that does not run on the machine changes nothing (on `--update` the release that works stays, with its record), and a rerun tries again. A failed copy, or a Ctrl+C or TERM while the files are staged, leaves nothing in `~/.local/bin` either. The manifest records each binary's sha256, and a file that no longer matches (a symlink, or a build you put there) is never overwritten by `--update` or removed by `--uninstall`, which then prints only the "Kept" line. When `~/.local/bin` is not on `PATH`, two marked lines go into `~/.zshrc`, for bash on macOS the first of `~/.bash_profile`, `~/.bash_login` and `~/.profile` that exists (a new `~/.bash_profile` only when none does, so it never hides an existing `~/.profile`), or `~/.bashrc` (bash on Linux), once; other shells get a hint. The manifest records one rc file: while its lines are still there, a run under another login shell prints the PATH hint instead of editing a second file, and the record's flags (file created, newline added) describe the lines now in that file, so `--uninstall` restores it byte for byte. Intel Macs, Windows and musl Linux get a build-from-source line. A checksum mismatch or a failed download installs nothing and is not fatal. `--update` installs a newer release; `--uninstall` removes the binaries it wrote, the directories it created when empty, and its two lines, leaving the rest of the rc file byte for byte.
  - Who answers: with `--yes` everything installs except the sign-in. With no terminal, or in an agent session without `--yes`, only stable-build and stable-build-mcp install, the guard stays off, and one line names what was left out and how to add it.
  - New flags: `--no-foundry`, `--no-login`, `--verbose`. New variable: `STABLE_BUILD_FOUNDRY_TAG`. The manifest records `tools.arcStudioCli` and `tools.arcFoundry` (with its `pathLine`), so `--uninstall` removes only what the installer added.
  - Tests: stubs for `npm`, `curl` (Arc Foundry releases from a fixture directory; any other URL fails) and `uname`, and an `arc-studio` stub whose `whoami` follows a state file that `login` sets. New round-trip scenarios cover Foundry (install, PATH lines, rerun, checksum mismatch, Intel Mac, a foreign `arc-forge`, `--no-foundry`, `--update`, uninstall), the npm path (install, failure, no npm, `--update`, uninstall order), `--verbose`, fatal-failure output, the Codex suffix, and on a pseudo-terminal: a "no" at the confirmation, answers that are neither yes nor no (asked again, then a no), the sign-in (done, already signed in, failed, `--no-login`, `--yes`, the only thing missing on `--update` and on a rerun) and fresh installs, with Claude Code alone and with both hosts, whose transcripts are printed and held to 25 lines. Also: a no-terminal run where npm, curl and the rc file are all wanted (only stable-build and its MCP plugin install), a node switch between runs, a failed plugin update, Foundry binaries that do not run, a binary the user replaced, bash with only `~/.profile`, a login shell switch, and rc flags after a re-add. The no-npm scenario runs without any `npm` on the system part of its PATH, so a distro npm in `/usr/bin` never runs.
  - Docs: `SECURITY.md` now describes what the installer does (npm install, Arc Foundry download with checksum, the sign-in, the files it writes outside its state directory and how `--uninstall` takes them out). Both READMEs (install section, options, what gets touched, uninstall), the `guide` skill (re-run the installer is the first fix for a missing Arc Studio CLI, sign-in or Arc Foundry) and the landing page ("One question, then everything is set up").
  - Fixes from review: `--update` in a terminal is no longer cancelled by a "no" to the third-party items it offers, which every v0.1.0 user sees on a first `--update` (before, stable-build itself was not updated). `--update` to an Arc Foundry release that fails `arc-forge --version` no longer deletes the release that works, and an interrupt during the copies no longer leaves `arc-*.tmp-<pid>` files in `~/.local/bin`. Digests are read from stdin, so a backslash in `--prefix`, `HOME` or `TMPDIR` no longer fails the checksum or makes the installer's own binaries look foreign. A dangling `~/.zshrc` symlink is not followed: no file is created at its far end, and `--uninstall` never deletes the link. `--uninstall` keeps the Arc Studio npm package while its Claude Code plugin is registered and `claude` is missing, and with a manifest it now runs without any host CLI, removing Arc Foundry and the PATH lines. A failed `arc-studio skills install` records the marketplace it already added, so `--uninstall` removes it before the npm package. An Arc Foundry already in `~/.local/bin` but not on `PATH` gets the rc file or the export line on its status line, and the `guide` skill reports that state with its own fix. The by-hand removal steps include `install.log`. `THIRD_PARTY_NOTICES.md` describes the Circle terms link, the npm install of the Arc Studio CLI and the Arc Foundry download. The round trip resolves system tools through a copy of `/usr/bin` and `/bin` without `arc-studio`, Arc Foundry, npm, claude, codex or curl, so a real one is never reached, and no check name starts with a quoted `~/` (shellcheck SC2088). New tests: `test/install/rc-helper.test.mjs` and round-trip scenarios F14 to F17, N5, N6 and T11.
- CI: `install.sh` is clean under shellcheck again. The closing message id `done` is now `fin_done` (SC1010), the language source `env` is quoted (SC2209), and the display-only `~` in `tilde()` carries a reasoned `disable=SC2088`.
- Vercel: a root `vercel.json` serves `site/` as static output with the same headers as `site/vercel.json`, so a Git push to `main` deploys the landing page instead of an empty 404 site. `test/site/site.test.mjs` keeps the two files in step.
- Installer: `config.json` is now written on install to hold the language, not only after you turn the guard on. A file that is not valid JSON is left untouched, with a warning.
- Guard hook: every finding, error or warn, is now non-blocking advisory output. The hook always exits 0 and prints one JSON object: `hookSpecificOutput.additionalContext` carries the findings for the agent (`[error]`/`[warn]` labels, rule id, file:line, fix, docs URL; still at most 5 findings and 2,000 characters), and `systemMessage` carries a one-line notice for the user ("stable-build guard: 1 Arc gotcha in src/history.ts (transfer-filter-no-emitter) — advisory, edit kept"). Error findings no longer exit 2, so Claude Code no longer labels them "blocking error". Consent gate, fail-open behavior and the latency budget are unchanged, and so are the `--scan` exit codes for CI. The session-start notice describes the new output.
- Guard `transfer-filter-no-emitter`: addresses are judged by value, including loop variables over a const array (`for (const e of EMITTERS)`, `.map`, destructuring), so a loop over both emitters is now an error (`both-emitters`); both emitters in separate queries of one file are a new warning (`split-emitters`); an Edit of only the `address` line re-checks the enclosing filter. Each variant has its own fix: replace 0x3600… with the system emitter, never add it next to 0x3600….
- Guard `getlogs-unpaged`: flags only ranges the RPC rejects (more than 10,000 blocks; re-verified live on both public endpoints on 2026-10-04). Exactly 10,000 blocks (`from + 10_000n - 1n`) is no longer reported. The fix explains -32014; notes record the undocumented -32602 result cap.
- Guard hook context: each finding now carries the dated docs quote behind its rule (`Docs: <url> says "<quote>" (checked <date>)`), so the agent can act on the fix when it cannot fetch the page. Over the 2,000-character cap, quotes are dropped first (last finding first), then docs links. `transfer-filter-no-emitter`'s `usdc-only` variant has its own quote (the system emitter logs native sends and ERC-20 transfers at 18 decimals; verified 2026-10-05); `--explain` prints variant quotes.
- Hook launcher (`run.sh`): always exits 0 and discards node's stderr, so a missing or broken plugin module (a partial install) no longer surfaces as a hook error with a Node stack trace. Previously a module that failed to load made the guard exit 1 before its own handlers ran.
- `guard.mjs --scan <subdir>` text output prints paths that open from the current directory.
- Skills: `guide` opens with what the kit is and handles `--plugin-dir` loads; `find-idea` lints chat-only ideas from stdin (`lint-ideas.mjs -`); `new-app` and `go-live` run plain `node` calls; `go-live` reads the checklist first and reports RPC calls and docs queries separately; `architecture` asks before registry and GitHub API checks; the fee floor is marked as documented for testnet.

## [0.1.0] - unreleased

First release.

### Added

- Marketplace `stable-build` for Claude Code (`.claude-plugin/marketplace.json`) and Codex (`.agents/plugins/marketplace.json`). It offers two plugins:
  - `stable-build`: skills for apps built on Arc, the data files they read, and an edit-time Arc gotcha guard. The guard stays dormant until the user opts in.
  - `stable-build-mcp` (optional): the Arc docs MCP server, plus Circle's codegen MCP server for Claude Code, both over HTTP.
- `install.sh`. It works only through the native `claude plugin` and `codex plugin` commands, keeps a manifest of what it added, and supports `--dry-run`, `--update` and `--uninstall`.
- Builder-journey skills: `guide` (with a catalog generated from skill frontmatter), `find-idea`, `new-app`, `gotchas`, `go-live` and `studio-delegate`.
- Role skills and shared workflows adapted from BMad Method v6.12.1 (tech writer from v6.10.0): `analyst`, `pm`, `ux-designer`, `architect`, `dev`, `tech-writer`, `product-brief`, `architecture`, `stories` and `layered-review`.
- Edit-time guard with 10 rules, each with a docs.arc.io or developers.circle.com quote and `verified_at`. It is advisory, local, and dormant until the user opts in. `guard.mjs --scan` runs the same rules on demand.
- Payouts starter (`new-app`): CSV payroll as `Memo.memo(USDC.transfer)` rows batched through `Multicall3From.aggregate3` from an EOA, receipt reconciliation into an 18-decimal ledger, idempotent resume, CLI and GitHub Pages workflow. Testnet by default.
- Data snapshots for `find-idea` and `go-live`: frontiers, programs (with `valid_until`), sample apps, ecosystem names/URLs/categories and their sources, plus a weekly refresh workflow.
- README with install paths, the full list of files and settings touched, skills, guard rules, uninstall and open UNVERIFIED items.
- Governance:
  - MIT license and third-party notices (BMad Method MIT notice; links to circlefin/skills and the Arc Studio CLI).
  - Security policy and contributing guide.
  - CI: shell syntax and shellcheck, node tests, the name and brand check, `claude plugin validate --strict`, an install round trip on macOS and Ubuntu, the payouts starter (scaffold, test, build, guard scan), and a weekly docs-drift check. Actions are pinned to commit SHAs.
